# 스펙: 이슈관리 (2026-07-10)

## 개요
화면 오류 이슈를 등록(스크린샷 첨부)·추적·해결하는 CRUD + 댓글. DB2(appuser) 신규 테이블. 패키지 `com.meritz.dash.issue`.

## DDL — `V020__create_issue_tables.sql` (번호 고정, 19c 호환만)
```sql
CREATE TABLE DASH_ISSUE (
    ISSUE_ID     NUMBER GENERATED BY DEFAULT AS IDENTITY,
    SCRN_ID      VARCHAR2(100)  NOT NULL,            -- 화면ID
    REG_EMPNO    VARCHAR2(30)   NOT NULL,            -- 작성자 사번
    ERR_CNTT     VARCHAR2(2000) NOT NULL,            -- 오류설명
    FILE_NM      VARCHAR2(255),                      -- 첨부 파일명
    FILE_CTYPE   VARCHAR2(100),                      -- 첨부 Content-Type
    FILE_DATA    BLOB,                               -- 스크린샷 원본
    STAT_CD      VARCHAR2(20) DEFAULT 'OPEN' NOT NULL,
    PRIR_CD      VARCHAR2(20) DEFAULT 'MEDIUM' NOT NULL,
    RSLV_CNTT    VARCHAR2(2000),                     -- 해결내용
    CREATED_AT   TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL,
    CREATED_BY   VARCHAR2(30),
    UPDATED_AT   TIMESTAMP,
    UPDATED_BY   VARCHAR2(30),
    CONSTRAINT PK_DASH_ISSUE PRIMARY KEY (ISSUE_ID),
    CONSTRAINT CK_DASH_ISSUE_STAT CHECK (STAT_CD IN ('OPEN','IN_PROGRESS','RESOLVED','CLOSED')),
    CONSTRAINT CK_DASH_ISSUE_PRIR CHECK (PRIR_CD IN ('LOW','MEDIUM','HIGH','CRITICAL'))
);
CREATE INDEX IX_DASH_ISSUE_STAT ON DASH_ISSUE (STAT_CD);

CREATE TABLE DASH_ISSUE_CMT (
    CMT_ID       NUMBER GENERATED BY DEFAULT AS IDENTITY,
    ISSUE_ID     NUMBER         NOT NULL,
    REG_EMPNO    VARCHAR2(30)   NOT NULL,
    CMT_CNTT     VARCHAR2(2000) NOT NULL,
    CREATED_AT   TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL,
    CREATED_BY   VARCHAR2(30),
    UPDATED_AT   TIMESTAMP,
    UPDATED_BY   VARCHAR2(30),
    CONSTRAINT PK_DASH_ISSUE_CMT PRIMARY KEY (CMT_ID),
    CONSTRAINT FK_DASH_ISSUE_CMT_DASH_ISSUE FOREIGN KEY (ISSUE_ID)
        REFERENCES DASH_ISSUE (ISSUE_ID) ON DELETE CASCADE
);
CREATE INDEX IX_DASH_ISSUE_CMT_ISSUE ON DASH_ISSUE_CMT (ISSUE_ID);
```

## API (전부 `/api/v1`, 인증=게이트웨이 인터셉터 자동, envelope `ApiResponse.of`)
| Method | Path | 권한 | 비고 |
|---|---|---|---|
| GET | `/issues?status=OPEN,IN_PROGRESS&screenId=` | 인증자 전원 | status 콤마 다중값, 화이트리스트 외 400. 미지정=전체. 목록엔 BLOB 미포함, `hasImage` 불리언 제공. 최신순(ISSUE_ID DESC) |
| GET | `/issues/{id}` | 전원 | 404 미존재. `hasImage`, `commentCount` 포함 |
| GET | `/issues/{id}/image` | 전원 | `ResponseEntity<byte[]>` + 저장된 Content-Type. 이미지 없으면 404 |
| POST | `/issues` | 전원 | **multipart/form-data**: `screenId`(필수) `content`(오류설명, 필수) `priority`(선택, 기본 MEDIUM) `image`(선택 파일). 201 + 생성 이슈 |
| PUT | `/issues/{id}` | 전원(협업 처리) | JSON, 전 필드 선택적 부분수정: `content,status,priority,resolveContent`. 404/400 |
| DELETE | `/issues/{id}` | **작성자 또는 ADMIN** | 아니면 403. 204 |
| GET | `/issues/{id}/comments` | 전원 | 오름차순 |
| POST | `/issues/{id}/comments` | 전원 | JSON `{content}` 필수. 이슈 미존재 404. 201 |
| PUT | `/issues/{id}/comments/{commentId}` | **댓글 작성자 또는 ADMIN** | 403/404 |
| DELETE | `/issues/{id}/comments/{commentId}` | **댓글 작성자 또는 ADMIN** | 204 |

## 비즈니스 규칙 (테스트로 고정)
1. `image`는 Content-Type이 `image/`로 시작해야 함. 아니면 400 (`IllegalArgumentException`).
2. status를 `RESOLVED`로 변경할 때 요청의 `resolveContent` 또는 기존 저장값 중 하나는 있어야 함. 둘 다 없으면 400.
3. status/priority 값은 화이트리스트 외 400.
4. 작성자(REG_EMPNO)=`AuthContext.empno()`. CREATED_BY/UPDATED_BY도 empno.
5. 삭제 권한: `empno==REG_EMPNO || role==ADMIN` → 아니면 `ForbiddenException`(403). 댓글 동일.
6. 목록 status 필터: 예) `status=OPEN,IN_PROGRESS`로 해결건 제외 조회.
